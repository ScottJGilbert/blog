## Notes

- Mobile Performance varies by 2-4 points between runs on the same page (e.g. the personal post measured 92-97 across five runs, `/personal` 93-98). Lighthouse mobile LCP is a *simulated* value computed from bytes transferred; on localhost everything finishes in about 150 ms, yet the model replays about 330 KB (HTML + 3 preloaded fonts + about 200 KB gzip of React/Next JS + CSS) at 1.6 Mbps.
- Independent in-browser measurement (Playwright + CDP, **real** Slow 4G 1.6 Mbps / 150 ms RTT, 4x CPU, cold cache, 412x823 @1.75 DPR; committed as `e2e/web/perf.spec.ts`, budget LCP < 2.5 s and CLS < 0.05):

  | Page | LCP (3 runs) | CLS |
  | --- | --- | --- |
  | / | 0.80 / 0.86 / 0.81 s | 0 |
  | /personal | 0.84 / 0.88 / 0.84 s | 0 |
  | /engineering | 0.88 / 0.85 / 0.82 s | 0 |
  | post (personal) | 1.06 / 1.06 / 0.94 s | 0 |
  | post (engineering) | 1.17 / 0.93 / 0.94 s | 0 |
  | /search?q=postgres | 0.80 / 0.80 / 0.79 s | 0 |
  | /login | 0.74 / 0.74 / 0.76 s | 0 |

- What was done for these numbers (vs. the first B3 build at 91-94 and Best Practices 96):
  - zod used to ride along in every page's JavaScript (via the shared API client imported into the header/newsletter/comments islands). It also tripped a CSP `unsafe-eval` browser issue (zod's JIT probe), which cost Best Practices 4 points. The browser client is now loaded lazily (`lib/browser-api.ts`), error checks are duck-typed (`lib/api-error.ts`) and two constants are mirrored in `lib/constants.ts`, so public pages ship none of it.
  - The comments island (`CommentsLazy`) downloads its code and fetches the thread only when the section is within 600 px of the viewport (or the URL targets `#comments`), into a reserved 28 rem box (CLS 0).
  - Header session state needs no network call for anonymous visitors (non-HttpOnly hint cookie `blog-auth`), so no 401 console errors and no extra request.
  - LCP image of the post page and the first card get `preload` + `fetchPriority="high"`; fonts keep A1's `display: optional` + preload.
  - Post-body CSS (`ViewerTheme.css`, `@blog/content/styles.css`, `post-prose.css`, KaTeX) is only imported by the post route, so listings, home and auth pages do not load it.
- Known cost: `katex.min.css` (5 KB gzip) is attached to every post route (Next bundles per route, `next/dynamic` did not make it conditional). The font files inside it are only fetched when equations render.

## Reproduce

```bash
# API (own DB + local uploads), then web
DATABASE_URL=postgres://blog:blog@localhost:5432/blog_b3 API_PORT=4103 BETTER_AUTH_URL=http://localhost:3103 SITE_URL=http://localhost:3103 \
  RATE_LIMIT_ENABLED=0 pnpm --filter @blog/api dev
cd apps/web && API_INTERNAL_URL=http://localhost:4103 SITE_URL=http://localhost:3103 DEV_PROXY=1 pnpm build && next start -p 3103
CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome npx lighthouse http://localhost:3103/personal --preset=desktop \
  --chrome-flags="--headless=new --no-sandbox"
```
